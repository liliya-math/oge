# Конструктор тестов · 31 октября 2026

Вход: `quiz-builder.html`, кнопка «Тесты» в режиме учителя кабинета. Прохождение: `quiz.html` по личному назначению. Демонстрация: `quiz.html?demo=1` (никаких записей на сервере).

## Разовое подключение

GitHub публикует страницы, но не обновляет Google Apps Script.

1. В Google Таблице кабинетов: Расширения → Apps Script.
2. Заменить текущий код содержимым `kabinet-apps-script.txt` версии 7.11 и сохранить.
3. Развернуть → Управление развёртываниями → карандаш → Новая версия → Развернуть. Сохранить действующий адрес веб-приложения.
4. Обновить конструктор. Должно появиться «Кабинет подключён».

Не запускать `setupDz` для подключения конструктора: эта старая функция перезаписывает демонстрационные работы прежней системы. Листы «Тесты» и «Попытки тестов» создаются автоматически. Новые разрешения, сторонние сервисы и API ИИ не требуются.

## Добавление работы

Загрузить TXT в UTF-8 или вставить текст → «Проверить и показать» → при необходимости «Редактировать» в карточке → «Сохранить работу» → выбрать одного или нескольких учеников → назначить. Используется существующий пароль преподавателя. Введённый в конструкторе пароль хранится только в памяти вкладки; уже сохранённый кабинетом пароль читается из `cab-admin`.

```
Название: Квадратные корни
Раздел: Алгебра / 8 класс / Квадратные корни

Задание: Вычисли \(\sqrt{81}\).
Ответ: 9
Баллы: 1

Задание: Реши уравнение \(x^2=25\).
Тип: набор
Ответ: -5; 5
Баллы: 2
Подсказка: Проверь положительное и отрицательное числа.
```

Типы: число (по умолчанию), набор, выбор, текст. Набор: числовые значения через `;`, порядок не важен. Выбор: поле «Варианты: первый | второй», ответ совпадает с текстом одного варианта. Число: десятичная запятая, точка, обыкновенная дробь `a/b`; несколько допустимых ответов через `|`. Текст: точное совпадение с нормализацией регистра и пробелов, варианты через `|`. Это не система символьной алгебры и не проверка доказательств. Допуск чисел 1e-9; целые сравниваются точно в пределах точности JavaScript Number.

Формулы вводить как LaTeX внутри `\(...\)` или `\[...\]`. Для отображения используется KaTeX с CDN, `trust:false`. Условия и подсказки экранируются; произвольный HTML не исполняется. На работу максимум 100 заданий, 1–10 баллов за задание и 40 000 символов JSON. Текстовый импорт не использует ИИ.

## Результаты

Каждая завершённая попытка - новая строка «Попытки тестов». Сохраняются ученик, работа, версия, назначение, ID отправки, время, баллы, максимум, ответы и проверка по заданиям. Повтор той же отправки возвращает имеющуюся попытку. Новый проход - новый ID. Проверка и итог только на сервере, ключи не отправляются ученику. Демо использует только публичный встроенный образец и ничего не записывает.

В кабинете, в разделе «Прогресс», видны все попытки, первая/последняя последовательность баллов, лучший результат, даты и график процентов. Группировка: раздел → работа и версия, чтобы не смешивать результаты разных условий. Учитель видит ту же историю в карточке ученика; родитель - в родительском режиме. Старая система `dz.html` и её результаты не мигрируются и не изменяются. Новые тесты не отправляют автоматических писем/Telegram.

Назначения закрепляют опубликованную версию. Правка создаёт новую версию, старая не перезаписывается. Владение заданием проверяется по действующей ссылке кабинета, строке ДЗ, работе, версии и случайному ID назначения. Используется существующий доступ по личной ссылке ученика; хранить её как личную. При смене кода история переносится; при удалении или сдвиге строки ДЗ устаревшая ссылка отвергается, а не привязывается к чужой строке. Проверенные задания остаются в архиве, из которого можно открыть тест повторно.

Статус домашки после первой автопроверки становится «Проверено». Повторные попытки обновляют историю, не перезаписывая комментарий учителя. Если обновление статуса не удалось, результат остаётся сохранённым, страница сообщает об этом отдельно. Черновики сохраняются только в текущем браузере, завершённые попытки синхронизируются через таблицу.

- `node tools/test_cabinet_workflow.cjs` и `node tools/test_study_resume.cjs`: совместимость с существующим workflow и сохранением позиции.
- Браузер: импорт образца, форма редактирования, формулы, прохождение демонстрации и повторная попытка, старый сервер показывает инструкцию без ложного сообщения об успешном сохранении.
- `tools/test_cabinet_homework.cjs` падает и на исходном HEAD: отсутствует `boardTaskLink` в контексте тестового мока. Этот старый тест не менялся.
- Реальная запись в Google Таблицу, назначение и история на нескольких устройствах требуют обновления Apps Script. При подготовке этой версии сервер в Google не развёрнут: нет авторизованного доступа к его редактору. Реальные ученики и их результаты для тестов не использовались.

## Типы работ и рисунки (1 ноября 2026)

В шапку работы добавляется строка `Тип работы: дз`, `сам` или `контр` (проверочная = `контр`). Без строки работа ведёт себя как раньше (свободные повторы).

| Тип | Подсказки | Попыток | Ученик видит | Ей |
|---|---|---|---|---|
| дз | одна на задание, берётся, учитывается | одна повторная попытка (всего две) | балл и список ✓/○ по заданиям, кнопка «Не знаю» | сколько подсказок и «не знаю» в истории |
| сам, контр | нет (отбрасываются сервером) | одна, сервер отклоняет вторую (`already_done`) | только балл | разбор по заданиям в карточке ученика |

К заданию можно добавить строку `Рисунок: fig-12.svg`. Файл кладётся в папку `quiz-fig/` (SVG, PNG или JPG, имя из латиницы, цифр, `-` и `_`). Подписи на рисунке не должны лежать на линиях: проверять `tools/urok/figcheck.py`.

В «Прогресс» один общий график процентов по всем работам в порядке выполнения: круг = дз, ромб = самостоятельная, квадрат = контрольная.

**Нужно обновить Apps Script** (ядро теста встроено в `kabinet-apps-script.txt`): шаги из раздела «Разовое подключение». Пока сервер старый, новые поля игнорируются, а работа с типом откроется как обычный тест.

Не сделано: пошаговое ДЗ как в старых страницах (две попытки на каждое задание с проверкой по ходу).

## Уведомление ученику о новом тесте (5 ноября 2026)

В конструкторе под выбором учеников есть галочка «Уведомить ученика в Telegram» (включена по умолчанию). Если у ученика подключён бот и нет паузы, он получит сообщение «Новый тест: название» с кнопкой, ведущей на его личный тест. Если не вышло, тест всё равно назначен, конструктор покажет, кому не ушло. Нужно вставить обновлённый `kabinet-apps-script.txt` в Apps Script и развернуть новую версию.

## Telegram преподавателю (1 ноября 2026)

После каждой новой попытки (дз, самостоятельная, контрольная) бот пишет тебе в личный чат: ученик, тип работы, название, балл и процент, номера неверных заданий, для дз подсказки и «не знаю», номер попытки, время и кнопка «Открыть карточку ученика». Повтор той же отправки сообщения не дублирует. Если Telegram недоступен, результат ученика всё равно сохраняется.

Подключение (один раз, нужен уже настроенный бот из `docs/telegram-homework.md`):
1. Вставить новый `kabinet-apps-script.txt` в Apps Script, сохранить, развернуть новую версию (как в «Разовом подключении»).
2. Обновить таблицу. В меню «Кабинет» появится «Подключить Telegram преподавателя».
3. Нажать его, открыть показанную ссылку в Telegram, нажать «Старт». Бот ответит «Готово!» в течение минуты.
4. Отключить: написать боту `/stop` из того же чата. Чат хранится только в Script Properties (`TG_TEACHER_CHAT`).


## Еженедельные пробники первой части (5 ноября 2026)

В кабинетах девятого класса добавлена вкладка «Пробники ОГЭ». У преподавателя и родителя аналитика находится отдельным блоком в карточке ученика. Демонстрация: `kabinet.html#demo`, вкладка «Пробники ОГЭ» (все данные вымышленные).

В конструкторе: «Пробник ОГЭ · Часть 1» → заполнить 19 условий и ключей → проверить → сохранить → назначить выбранным ученикам со сроком. Можно загружать готовый TXT с шапкой:

```
Название: Пробник №1
Раздел: ОГЭ / Пробники / Часть 1
Тип работы: контр
```

Этот раздел служит явной меткой пробника. Он проверяется на сервере: ровно 19 заданий по 1 баллу и тип «контр». Порядок условий соответствует номерам 1–19; номера не извлекаются из произвольного текста условия. Пробники с другим порядком заданий нужно привести к этому порядку перед загрузкой. Одна попытка без подсказок. Сдача попадает в аналитику автоматически после обновления кабинета, отдельного ввода баллов нет.

График последних 12 работ, вся история в таблице, последний/лучший балл, изменение с первого пробника, ошибки последней работы. Последние три пробника определяют карту: две или три ошибки = «Повторить», три верных = «Уверенно», остальные проверенные = «Закрепить». До трёх работ сильные места не объявляются. Пропуск ответа учитывается как неверное решение; причина ошибки не определяется. В динамику входит первая сдача каждого назначения. Обычные тесты и другие разделы исключаются. Перевода в оценку за полный экзамен нет.

Требуется сервер **7.13**. Страница `kabinet-code.html` загружает текущий серверный файл с кнопкой «Скопировать код». Заменить основной код Apps Script, сохранить, обновить существующее развёртывание через «Новая версия». Запускать setup/setupDz не нужно. Без нового сервера сохранение пробников в конструкторе заблокировано с объяснением; обычные тесты продолжают работать. Новых листов или миграции не требуется. Для отмеченных пробников ученик и родитель получают только номера и признаки верности (`mock.tasks`) и длительность, без ключей/ответов/условий; подробности остальных видов работ по-прежнему доступны только преподавателю. История привязана к коду ученика, чужие записи не возвращаются.

Проверки: `node --test tests/quiz.node-test.cjs tests/oge-progress.node-test.cjs`; браузерная проверка демонстрационной вкладки и графика. Реальная отправка и чтение между устройствами требует обновления развёртывания Google Apps Script; автоматически в Google эта версия не развёрнута.

## Отметка уже сохранённых пробников (5 ноября 2026, сервер 7.14)

В списке «Сохранённые работы» у каждой работы есть «Отметить как пробник» и обратное действие «Убрать из пробников». Отметка применяется к всем версиям работы, в которых ровно 19 заданий по одному баллу. Неподходящие старые версии пропускаются с сообщением; неподходящая последняя версия отклоняется. Содержимое тестов, назначения и JSON сохранённых попыток не переписываются. Прежние результаты и проверка по номерам подключаются при следующем чтении кабинета. Новые версии наследуют отметку; при изменении формата нужно её снять. В редакторе для новых работ добавлен флажок «Пробник ОГЭ · Первая часть»; обязательного шаблона больше нет. Отметка отвечает за аналитику и не меняет тип и правила прохождения существующей работы. Для новых работ с одной попыткой используется «Тип работы: контр».

Сервер хранит отметки отдельно на автоматически создаваемом листе «Виды тестов» (работа, версия, boolean, дата). Прочитать и изменить отметки можно только с паролем преподавателя; просмотр учеником продолжает фильтровать историю по его коду. Снятие отметки обратимо и не удаляет результаты. `ogePart1` в истории имеет приоритет над старой меткой раздела, включая явное `false`. Возможность включается по `ogeMocks:2` из capabilities. Пока сервер старый, кнопки классификации отключены, рядом ссылка на обновление. Новая версия кода: **7.14**; `kabinet-code.html` содержит актуальную кнопку копирования.

Проверки дополнены реальным сценарием в эмуляторе таблиц: старая работа и сдача → отметка → история и карта ошибок → новая версия → снятие отметки. Проверено побайтовое сохранение условий, ключей, назначений и попыток, пропуск несовместимой версии, отказ чужому/неавторизованному запросу и устаревшей версии, наследование отметки и её снятие для работ со старой меткой раздела.

При проверке действующего веб-приложения ответ `?quiz=capabilities` содержал `ogeMocks: 2`. Эта проверка подтверждает подключение Apps Script 7.14 независимо от публикации страниц GitHub Pages.

## Ограничение по времени (8 ноября 2026)

В шапку работы добавляется строка `Время: 15` (целое число минут, 1-180, можно писать «15 мин»). Без строки время не ограничено. Подходит любому типу работы; для теста по теории и контрольной ставят `Тип работы: контр` или `сам`.

Как работает: до нажатия «Начать» ученик видит только правила, условий в ответе сервера нет. Кнопка «Начать» фиксирует на сервере старт (лист «Старты тестов»), перезагрузка страницы старт не сбрасывает. На странице идёт обратный отсчёт, последняя минута красная. Когда время выходит, введённые ответы отправляются сами. Если сдача пришла позже срока больше чем на 45 секунд (например, пропала связь), результат сохраняется, но помечается «Сдано с опозданием», и это приходит тебе в Telegram. Если отметки о старте нет, помечается «время не проверено». Секунды в таблице считает сервер, а не браузер.

Ограничение: ученик без сети может продолжать вводить ответы после срока, поэтому решение по опоздавшим работам остаётся за тобой, сервер их не обнуляет.

Подключение: вставить `kabinet-apps-script.txt` в Apps Script и сделать «Новая версия». Пока сервер без таймера, конструктор не даст сохранить работу со строкой `Время`. Демонстрация таймера: `quiz.html?demo=1&t=1` (минуты в параметре `t`).

## Пачка файлов (8 ноября 2026)

Кнопка «Загрузить пачку .txt» в конструкторе сохраняет сразу много работ и прикрепляет каждую к квадратику. Квадратик берётся из имени файла: фрагмент вида `8A-109`, `8A-952`, `7G-23` между дефисами или точкой (`dz-8A-109-тема-variant-01.txt`). Нет id в имени - работа сохранится без прикрепления. Работа с тем же названием сохраняется новой версией, а не копией. Если на квадратике уже 10 работ, новая сохранится, но не прикрепится. Нужен вход преподавателя. Править Apps Script для этого не нужно.
